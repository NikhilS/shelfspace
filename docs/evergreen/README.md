## I. Executive Philosophy & The Modern Archivist

**book(ish)** is designed after the quiet focus and tangible permanence of a private scholarly library. It pairs physical-heritage craftsmanship with modern computing utility to create a durable, tactile, and enjoyable digital library system.

Every technical, typographic, and architectural decision in this repository must uphold three governing tenets:

1. **Craftsmanship over Clutter:**
   We strictly reject modern "AI slop"—arbitrary glassmorphism, heavy saturated purple-to-blue gradients, glowing drop shadows, and unsolicited widgets. Visual depth comes from **tonal layering**, crisp geometric typography, and generous negative space.
2. **Unified Data Authority & Gateway Architecture:**
   We maintain a unified data plane where 100% of data queries and mutations route through a single, type-safe tRPC v11 Gateway backed by `firebase-admin/firestore` on the server. The browser client application never imports or directly invokes the Firestore client SDK, and `firestore.rules` is permanently sealed (`allow read, write: if false;`).
3. **Deterministic Performance & Zero-Cost Observability:**
   Telemetry and debugging HUDs must never degrade user-perceived performance. Heavy operations (UMAP vector dimensionality reduction, image processing) execute off the main thread in Web Workers. Synchronous serialization and memory allocations are banned on critical render paths.

## II. The "Golden Rules" (Non-Negotiable Invariants)

These rules apply to every pull request, feature branch, and refactor:

| Domain                | Invariant Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| :-------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Security**          | **Direct client Firestore Web SDK usage is strictly forbidden.** Never re-introduce `firebase/firestore` into client bundles, and keep `firestore.rules` locked to `if false`. All client reads and mutations pass through server procedures with runtime Zod validation, RBAC/ABAC checks, and `firebase-admin/firestore`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Typography**        | **Strict Geometric Sans Display + UI Sans + Tabular Mono Rule (NEVER Use or Suggest Serif Fonts).** `Plus Jakarta Sans` (`--font-serif` / `--font-headline-*`) powers display headings, book titles, and drop caps; `Manrope` (`--font-sans`) powers all UI controls, metadata kickers, rationales, and body prose; `JetBrains Mono` / `tabular-nums` (`--font-mono`) powers numeric metrics, publication years, ISBNs, and coordinates; and `Playfair Display` (Italic) is strictly reserved solely for the `book(ish)` brand wordmark (`--font-brand`). **Never introduce, apply, or suggest serif fonts (e.g., `Fraunces`, `Georgia`, `Newsreader`, `Source Serif`) anywhere in the application or future design proposals.** |
| **Aesthetics**        | **No Pill Buttons for Actions.** Action buttons and tags must use rectilinear corners (`rounded` 4px or `rounded-lg` 8px) to respect the rectangular proportions of books and catalog cards.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **State**             | **No `skipToken` React Query Abuses & Normalized Zero-Refetch Cache Reconciliation.** TanStack Query must never be used as a manual key-value store. Because client queries use a 5-minute `staleTime` (60m for warm `book.list` caches backed by `book.syncChanges`) with `refetchOnWindowFocus: false`, a normalized client entity store (`src/stores/entityCacheStore.ts` with monotonically versioned rollback guards), and 7-day UID-indexed sharded structured-clone IndexedDB persistence (`bookish-cache-v3` with `by_uid` index), single-book and status mutations must optimistically patch (`applyOptimisticReadingStatusPatch`, `applyOptimisticBookEditPatch`, `removeBookFromReadingCaches`) and surgically commit authoritative server deltas (`commitReadingStatusDelta`, `commitBookUpsertDelta`, `commitBookDeleteDelta`, `commitBookReviewDelta` in `src/lib/readingStatusCache/`) across `useEntityCacheStore` and **all** coupled query projections (`readingTracker.getShelf`, `readingTracker.getUnreadLibraryBooks`, `book.list`, `book.get`, `library.get`, `library.list`) without triggering full-collection refetch storms. Ephemeral UI state belongs in Zustand; URL parameters govern filterable views. |
| **Telemetry**         | **Never `JSON.stringify` or allocate `Blob`s on the render path.** Payload calculations and telemetry logging must be deferred to `requestIdleCallback` or lightweight heuristics.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **API & Persistence** | **100% Read/Write Zod Schema & Converter Compliance.** Input and output schemas defined in `src/schemas/` drive all tRPC v11 routers and runtime validation. Every single Firestore read and write across all 12 collections (`users`, `readingStates`, `libraries`, `books`, `bookDetails`, `reviews`, `allowedDuplicates`, `jobs`, `tombstones`, `allowlist`, `waitlist`, `geolocationCache`) must pass through a typed `*Converter` (`fromFirestore` / `toFirestoreWrite`) and shared strict validators (`validateFirestoreReadPayload`, `validateFirestoreWritePayload`, `validateIncomingApiData`). Container-local disk caches (e.g., `.cache/geocache.json`), raw `.data() as ...` casts, and unvalidated `.set()`/`.update()` calls are forbidden.                                                                                                                                                                                                                                                                                                                                                                          |
| **Database**          | **No Orphaned Books.** A book document cannot exist outside of a parent `libraries/{libraryId}/books/{bookId}` path. All library deletions must clean up subcollections.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Voice & Microcopy** | **Warm, Friendly, Crisp.** All user-facing headings, descriptions, empty states, and modals speak in a warm, welcoming bookshop voice with crisp, concise phrasing—free of database or systems jargon (`records`, `payloads`, `leaks`, `volumes`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Code Style**        | **Google TypeScript Style Guide (`gts`).** Enforce named exports only (no `export default` in `src/`), named `function` declarations over exported arrow functions and `React.FC`, no Hungarian `I` prefixes on interfaces (`MetadataPlugin`, not `IMetadataPlugin`) or `T` prefixes on multi-letter generics (`<Output>`, not `<TOutput>`), whole-word CamelCase for acronyms (`Csv`, `Isbn`, `Hud`), `interface` for object shapes, braced control flow (`curly`), no redundant `public` modifiers, and zero `any` across both production and test files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
